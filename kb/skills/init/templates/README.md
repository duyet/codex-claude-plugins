# kb

A plain-text knowledge base that every coding agent reads from and writes to. Write a fact once and every agent and session uses it.

It is plain markdown with no database, atomic notes, an index-first read (`MEMORY.md`), `[[wikilinks]]` and tags for a graph view (Obsidian or `kb viz`), and a `DREAM.md` pass that keeps it tidy. `memory/` is a conformant [OKF v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) bundle.

## Layout

- `AGENTS.md` is the protocol for all agents. `CLAUDE.md` points to it.
- `DREAM.md` is the consolidation pass. `MEMORY.md` is the index.
- `memory/` holds the notes, nested under `<group>/`. `index.md`, `log.md`, and `viz.html` are generated by `kb gen`. `_TEMPLATE.md` is the note standard.
- `raw/` holds the capture inbox (`raw/inbox/`) and source docs.
- `bin/kb` and `scripts/` are the CLI. `.agent/state.json` holds ingest state.

## Use

- Read: `kb index`, open the relevant notes, and fetch a note's `sources:` for depth.
- Write: `kb capture "note"` when unsure, or a standard note in `memory/<group>/` for a keeper. Then `kb lint && kb gen`, and `kb sync` if there is a git remote.
- Dream: run `DREAM.md` periodically or with `/loop`.

Put the CLI on PATH with `export PATH="<this-directory>/bin:$PATH"`.

```bash
kb capture "rough note"   # raw/inbox/<today>.md
kb ingest <file>          # add a source doc to raw/
kb index | kb lint | kb sync | kb dream | kb root
kb gen | kb viz           # regenerate (and open) index.md files and viz.html
kb wire on|off            # add or remove the reflex block in agents' global config
kb autosync on|off|status # opt-in 15 minute sync cron, needs a git remote
```

`scripts/wire.sh on` adds a small marked block to each existing agent global instruction file (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.config/opencode/AGENTS.md`) so new sessions read `MEMORY.md`. `scripts/wire.sh off` removes it.

For version control, run `git init` and add a remote. If the repo is public, keep only general, public knowledge in it (`AGENTS.md` section 3).
